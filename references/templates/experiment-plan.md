## 使用方式

复测判据（guide Steps 16–17）回答"怎样算显著"；本模板回答"这个实验到底在测什么"。
两者缺一：没有判据的实验无法判定，没有前置记录的实验无法追溯。

## 模板

```text
问题：本实验要回答什么问题？支持什么决策？
主指标：唯一主指标（吞吐/延迟/耗时/带宽……），优化目标以它计
次指标与回归指标：可能被该改动拖累的指标（内存、启动、P99、精度……）
基线实现：commit 或可复现构建方式
候选实现：commit 或可复现构建方式
语义等价要求：输出必须逐位一致 / 容差内一致 / 仅性能对比（说明依据）
代表性输入来源：真实负载/生产采样/合成数据（说明代表性依据）
预期运行区间：正常/峰值/边界输入范围
目标运行时：语言运行时、GC 模式、JIT 预热策略
目标架构：CPU 架构/核心数/缓存层级约束
部署形态：常驻服务/批处理/库调用（影响指标选择）
机器与电源策略：机型、锁频方式、独占/共享、thermal 状态
运行次数与停止规则：轮数、每轮迭代数、预声明的作废/重跑规则
可接受回归阈值：双阈值（相对 % + 绝对下限），预声明后才允许开跑
```

## 纪律

- 阈值**先于实验**声明，禁止看到结果后再定"显著"标准。
- 输入分布改变 = 换了实验，须重新填表并重跑基线。
- 语义等价要求为空 = 该改动不满足"优化"定义（先改对，再谈快）。
